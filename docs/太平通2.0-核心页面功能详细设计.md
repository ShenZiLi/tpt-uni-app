# 太平通 2.0 核心页面功能详细设计

## 1. 文档说明

### 1.1 文档目的

本文档用于指导太平通 2.0 微信小程序原型的页面设计和后续开发，明确页面目标、信息结构、交互行为、Mock 数据和验收标准。

本文档配套阅读：

- [太平通2.0 微信小程序原型技术选型与设计文档](./太平通2.0-微信小程序原型技术选型与设计文档.md)
- [保险类产品亮点功能调研](./保险类产品亮点功能调研.md)

### 1.2 原型范围

本版本用于汇报展示和基本操作，所有业务数据使用本地 Mock，不接入真实登录、保单、理赔、AI、医疗、支付或后台服务。

### 1.3 核心产品主张

> 太平通 2.0 不是“保险功能入口集合”，而是帮助用户看懂保障、管理家庭风险并获得下一步行动的风险管理伙伴。

核心组合：

```text
吉象 AI 顾问
  + 家庭保障总览
  + 保单随存随懂
  + 保单健诊
  + 闪赔协助
  + 健康行动
```

## 2. 体验原则

### 2.1 页面原则

- 每个页面只突出一个主要任务；
- 先展示用户状态，再展示建议和行动；
- 复杂保险术语必须提供大白话解释；
- 所有核心按钮都要有明确反馈；
- 页面不展示无法完成的空入口；
- 原型演示优先保证流程稳定和可重复。

### 2.2 视觉原则

- 背景：浅薰衣草或低饱和蓝紫；
- 容器：玻璃感白色大圆角卡片；
- 文字：深靛蓝为主，灰蓝为辅助；
- 强调：蓝紫渐变用于吉象 AI 和主操作；
- 状态：翡翠绿表示完成或健康，柔和橙表示提醒或待处理；
- 导航：底部使用悬浮胶囊式 TabBar；
- 吉祥物：使用太平通自有“吉象” IP，不复用外部产品角色形象。

### 2.3 业务边界

- AI 只提供信息解释和服务导航，不替代理赔、核保或医疗结论；
- 理赔页面只模拟流程和材料准备，不展示真实审核结果；
- 保障缺口只做演示分析，不直接生成具有销售承诺的投保结论；
- 健康数据只用于展示任务和积分，不直接参与保险定价；
- 银发版的家人代办只展示入口和授权提示，不实现真实身份授权。

## 3. 页面与导航结构

### 3.1 底部 Tab

| Tab | 页面 | 主要任务 |
| --- | --- | --- |
| 首页 | `/pages/index/index` | 查看当前状态和待办 |
| AI 顾问 | `/pages/ai/index` | 查询、理解和获得服务建议 |
| 保单 | `/pages/policy/index` | 管理个人及家庭保单 |
| 我的 | `/pages/mine/index` | 管理家庭、设置和体验模式 |

### 3.2 非 Tab 页面

| 页面 | 建议路径 | 入口 |
| --- | --- | --- |
| 保单详情 | `/pages/policy/detail` | 保单列表、AI 结果、家庭中心 |
| 家庭保障中心 | `/pages/family/index` | 首页家庭卡片、我的 |
| 保单健诊 | `/pages/family/diagnosis` | 家庭中心、首页缺口卡片 |
| 闪赔协助 | `/pages/service/claim` | 首页快捷服务、AI 结果 |
| 理赔进度 | `/pages/service/claim-progress` | 闪赔提交成功、首页待办 |
| 产品对比 | `/pages/service/compare` | 产品列表、AI 建议 |
| 健康行动 | `/pages/service/health` | 首页健康卡片、我的 |
| 主题设置 | `/pages/mine/theme` | 我的、设置 |

### 3.3 全局跳转规则

- Tab 页面之间使用 `switchTab`；
- 普通业务页面使用 `navigateTo`；
- 从详情返回列表时保留筛选和滚动位置；
- 提交成功页只能通过“查看进度”或“返回首页”离开；
- AI 结果卡片可以跳转到保单详情、家庭中心或闪赔协助；
- 所有页面支持系统返回和页面内返回按钮。

## 4. 全局组件和状态

### 4.1 全局组件

| 组件 | 功能 | 适用页面 |
| --- | --- | --- |
| `TpPageShell` | 页面背景、安全区和滚动容器 | 所有页面 |
| `TpGlassCard` | 玻璃感白卡容器 | 所有内容页 |
| `TpSectionHeader` | 标题、说明和查看更多 | 首页、保单、健康 |
| `TpPrimaryButton` | 主操作按钮 | 表单、提交、开始分析 |
| `TpStatusTag` | 状态标签 | 保单、理赔、家庭 |
| `TpEmptyState` | 空状态提示和操作 | 列表、家庭、理赔 |
| `TpLoadingState` | 加载和 AI 思考态 | AI、健诊、理赔 |
| `TpToast` | 操作反馈 | 全局 |
| `JixiangAvatar` | 吉象头像和状态 | 首页、AI、结果卡片 |
| `FloatingTabBar` | 悬浮胶囊 TabBar | 主 Tab 页面 |

### 4.2 通用状态

每个需要异步或模拟异步的模块统一使用：

```ts
type ViewState = 'idle' | 'loading' | 'success' | 'empty' | 'error'
```

状态要求：

- `idle`：展示可操作的初始状态；
- `loading`：展示骨架或吉象思考动画；
- `success`：展示业务结果和下一步操作；
- `empty`：说明原因，并提供替代入口；
- `error`：说明当前为演示数据或操作失败，并提供重试。

## 5. 首页详细设计

### 5.1 页面目标

首页回答三个问题：

1. 我当前的保障状态是什么？
2. 今天最值得处理什么？
3. 我可以从哪里获得帮助？

### 5.2 模块顺序

```text
顶部问候
  ↓
吉象 AI 顾问卡片
  ↓
待办事项
  ↓
家庭保障摘要
  ↓
快捷服务
  ↓
健康行动
```

### 5.3 模块设计

#### 顶部问候

字段：

- 用户昵称：`Viz` 或 Mock 用户名；
- 日期：当前日期或固定演示日期；
- 一句话状态：如“今天的保障状态良好，有 1 项待关注”。

操作：

- 点击头像进入“我的”；
- 点击通知图标展示消息弹层；
- 点击设置入口进入主题设置。

#### 吉象 AI 顾问卡片

内容：

- 吉象头像或插画；
- 问候文案；
- 推荐问题；
- “问问吉象”主按钮。

推荐问题示例：

- 我有哪些医疗保障？
- 家里谁的保障比较薄弱？
- 这张保单什么时候续费？

交互：

- 点击卡片或按钮进入 AI 页面；
- 点击推荐问题后带入 AI 对话并自动触发 Mock 回复。

#### 待办事项

字段：

- 待办类型：续费、补材料、保障缺口、健康任务；
- 标题；
- 截止时间或状态；
- 操作按钮。

示例：

```text
医疗险将在 18 天后续费       去查看
理赔申请还差 1 份材料         去补充
家庭保障有 2 项待关注          去健诊
```

状态：

- 无待办时展示“目前没有紧急事项”；
- 点击待办进入对应业务页；
- 完成操作后从列表中移除或更新状态。

#### 家庭保障摘要

内容：

- 家庭成员数量；
- 总保障额度；
- 保障完整度；
- 缺口数量；
- “查看我的家”按钮。

交互：点击进入家庭保障中心。

#### 快捷服务

建议入口：

- 我要理赔；
- 保单健诊；
- 产品对比；
- 医疗服务。

使用两列圆角卡片，每个入口必须有图标、标题、辅助说明和明确跳转。

#### 健康行动

字段：

- 当前任务；
- 连续打卡天数；
- 健康积分；
- 今日操作按钮。

交互：

- 点击“完成今日步行”更新任务状态；
- 完成后展示绿色反馈和积分增加；
- 点击卡片进入健康行动页。

### 5.4 首页验收

- [ ] 首屏能够看到吉象 AI、待办和家庭保障摘要；
- [ ] 四个快捷服务都能进入对应页面；
- [ ] 待办至少有一条可以完成闭环；
- [ ] 健康任务点击后状态发生变化；
- [ ] 页面符合浅薰衣草和玻璃感白卡视觉规范。

## 6. AI 顾问页详细设计

### 6.1 页面目标

用自然语言降低用户理解保险和寻找服务的成本。

### 6.2 页面结构

```text
顶部导航
  ↓
吉象欢迎区
  ↓
推荐问题
  ↓
对话消息区
  ↓
业务结果卡片
  ↓
底部输入区
```

### 6.3 消息类型

| 类型 | 说明 |
| --- | --- |
| 用户消息 | 用户输入或点击推荐问题产生 |
| 吉象文本回复 | 大白话解释和建议 |
| 保单结果卡片 | 展示保单摘要和查看详情按钮 |
| 服务动作卡片 | 跳转理赔、健诊或家庭中心 |
| 风险提示 | 信息辅助和非正式结论说明 |

### 6.4 推荐问题

- 我有哪些医疗保障？
- 这张保单保什么？
- 家庭保障有没有缺口？
- 这次住院需要准备什么材料？
- 帮我看看这两款产品有什么不同？

### 6.5 Mock 对话规则

| 输入关键词 | Mock 结果 |
| --- | --- |
| 医疗保障 / 保单 | 医疗保单摘要 + 查看详情 |
| 缺口 / 家庭 | 家庭保障摘要 + 去健诊 |
| 理赔 / 住院 | 材料准备建议 + 去闪赔 |
| 对比 / 产品 | 产品对比卡片 |
| 其他 | 通用提示 + 推荐问题 |

交互流程：

1. 用户点击推荐问题或输入内容；
2. 页面追加用户消息；
3. 显示 600～1000ms 的吉象思考态；
4. 显示预设回复；
5. 根据回复展示业务卡片；
6. 点击卡片进入对应页面。

### 6.6 AI 边界提示

每次涉及理赔、医疗或产品建议时，在回复底部显示：

> 以上内容为信息辅助，具体结果以正式合同、审核及专业人员意见为准。

### 6.7 AI 页验收

- [ ] 推荐问题可以直接触发回复；
- [ ] 输入框、发送按钮和键盘行为正常；
- [ ] 思考态和回复态有明显区别；
- [ ] 回复可跳转保单、健诊或理赔页面；
- [ ] 未知问题不会出现空白页面；
- [ ] 不展示医疗诊断或保证获赔结论。

## 7. 保单列表页详细设计

### 7.1 页面目标

让用户快速找到自己或家庭成员的保单，并进入保单详情。

### 7.2 页面结构

```text
页面标题
  ↓
保障总览卡片
  ↓
分类筛选
  ↓
保单列表
```

### 7.3 保障总览卡片

展示：

- 保单数量；
- 总保额；
- 生效中保单数量；
- 待续费数量；
- 保障缺口提醒。

点击缺口提醒进入保单健诊。

### 7.4 筛选项

- 全部；
- 人身保障；
- 健康保障；
- 财产保障；
- 即将续费。

### 7.5 保单卡片

字段：

- 产品名称；
- 被保人；
- 产品类型；
- 保额；
- 保单状态；
- 到期或续费日期；
- 查看详情按钮。

状态：

- 生效中：绿色标签；
- 即将续费：橙色标签；
- 已暂停：灰色标签。

操作：

- 点击卡片进入详情；
- 点击收藏切换收藏状态；
- 下拉刷新 Mock 列表；
- 无保单时进入空状态，引导添加演示保单。

### 7.6 列表页验收

- [ ] 分类筛选结果正确；
- [ ] 保单状态颜色和文字一致；
- [ ] 点击卡片可以进入对应详情；
- [ ] 空状态有明确说明和操作入口；
- [ ] 返回后保留当前分类。

## 8. 保单详情页详细设计

### 8.1 页面目标

把复杂保单转成用户可以快速理解和行动的信息。

### 8.2 页面结构

```text
保单头部信息
  ↓
保障摘要
  ↓
保什么
  ↓
不保什么
  ↓
什么时候可以用
  ↓
理赔案例
  ↓
服务操作
```

### 8.3 信息模块

#### 保单头部

- 产品名称；
- 被保人；
- 保单状态；
- 生效日期；
- 续费日期；
- 收藏按钮。

#### 保障摘要

- 保额；
- 保障期限；
- 年缴或月缴金额；
- 免赔额；
- 保障标签。

#### 条款解读

使用四块结构：

1. 保什么；
2. 不保什么；
3. 什么情况下可以用；
4. 下一步怎么办。

每块默认折叠或展示摘要，点击后展开详细说明。

#### 理赔案例

只使用经过脱敏的 Mock 案例，字段包括：

- 出险场景；
- 申请材料；
- 处理结果；
- 过程说明。

不得使用未经确认的真实赔付金额、处理时长或获赔率。

#### 服务操作

- 去理赔；
- 问问吉象；
- 查看家庭保障；
- 下载电子保单（原型只展示成功反馈）。

### 8.4 详情页验收

- [ ] 用户能在首屏看到产品、被保人和状态；
- [ ] “保什么 / 不保什么 / 下一步怎么办”结构清晰；
- [ ] 理赔案例与产品相关；
- [ ] 操作按钮都能跳转或反馈；
- [ ] 不出现“保证获赔”等绝对表述。

## 9. 家庭保障中心详细设计

### 9.1 页面目标

以家庭为单位展示成员保障状态，帮助用户理解整体风险。

### 9.2 页面结构

```text
我的家标题
  ↓
家庭成员横向切换
  ↓
家庭保障总览
  ↓
成员保障卡片
  ↓
保障缺口
  ↓
保单列表
```

### 9.3 家庭成员切换

默认 Mock 成员：

- 本人；
- 配偶；
- 父亲；
- 母亲；
- 子女。

操作：

- 点击成员切换当前视图；
- 点击“+”展示添加成员弹层；
- 添加成员只写入本地状态；
- 长按或点击编辑进入成员信息 Mock 页面。

### 9.4 保障总览

展示：

- 家庭总保障额度；
- 成员数量；
- 已覆盖风险类型；
- 待关注成员数量；
- 保障完整度。

建议使用环形进度和三种状态：已覆盖、待关注、存在缺口。

### 9.5 缺口卡片

示例：

```text
母亲 · 医疗保障
当前状态：待关注
原因：住院医疗保障额度较低
操作：让吉象帮我分析
```

点击后进入保单健诊，页面展示分析依据和 Mock 建议。

### 9.6 家庭中心验收

- [ ] 成员切换会更新对应保单信息；
- [ ] 首页和我的页面都能进入家庭中心；
- [ ] 缺口卡片可跳转保单健诊；
- [ ] 添加成员有完成反馈；
- [ ] 页面不直接输出具体购买承诺。

## 10. 保单健诊页详细设计

### 10.1 页面目标

把家庭保单转化为可理解的保障分析结果，而不是直接销售产品。

### 10.2 分析流程

```text
选择家庭成员
  → 选择关注风险
  → 吉象分析态
  → 五维保障结果
  → 缺口清单
  → 下一步服务
```

### 10.3 五维分析

- 医疗保障；
- 重疾保障；
- 意外保障；
- 家庭责任；
- 养老储备。

每个维度展示：

- 当前状态；
- 简短解释；
- 风险等级；
- 需要关注的原因。

### 10.4 结果页面

模块：

1. 总体评分或完整度；
2. 五维雷达图；
3. 缺口清单；
4. 重复保障提示；
5. 吉象解释；
6. 查看相关保单或产品对比。

### 10.5 结果表述

使用：

- “建议进一步了解”；
- “当前保障存在待关注项”；
- “可以结合家庭实际情况继续评估”。

避免：

- “必须购买”；
- “最适合你”；
- “保证解决风险”；
- “不买就会有损失”。

### 10.6 健诊页验收

- [ ] 分析流程有开始、加载和结果状态；
- [ ] 五维结果可视化清晰；
- [ ] 缺口清单有解释和下一步动作；
- [ ] 分析结果能跳转到保单或产品对比；
- [ ] 结果文案不构成强制购买建议。

## 11. 闪赔协助页详细设计

### 11.1 页面目标

降低用户开始理赔的心理和操作门槛，展示清楚的材料准备路径。

### 11.2 页面结构

```text
选择事故类型
  ↓
确认被保人和保单
  ↓
材料清单
  ↓
拍照 / 上传入口
  ↓
材料确认
  ↓
提交成功
```

### 11.3 事故类型

- 住院医疗；
- 门诊医疗；
- 意外受伤；
- 重疾申请；
- 其他。

### 11.4 材料清单

根据事故类型展示 Mock 清单：

- 身份证明；
- 医疗票据；
- 诊断证明；
- 出院记录；
- 银行账户信息。

每项状态：未上传、已上传、待确认。

### 11.5 拍照和上传

原型行为：

- 点击拍照后显示模拟识别加载态；
- 加载完成后把材料状态更新为已识别；
- 点击相册上传显示模拟文件名；
- 不真正调用 OCR 或上传接口。

页面提示：

> 当前为演示流程，材料识别结果不代表正式审核结论。

### 11.6 提交结果

提交成功页展示：

- 模拟申请编号；
- 当前状态：已提交；
- 下一步：等待材料审核；
- 查看理赔进度；
- 返回首页。

### 11.7 闪赔页验收

- [ ] 事故类型可以选择；
- [ ] 被保人和保单可以确认；
- [ ] 材料清单随事故类型变化；
- [ ] 上传动作有识别反馈；
- [ ] 未完成必要材料时不能提交；
- [ ] 提交后可以进入理赔进度页。

## 12. 理赔进度页详细设计

### 12.1 页面目标

让用户知道理赔处理到哪一步、还需要做什么。

### 12.2 页面结构

```text
申请摘要
  ↓
当前状态
  ↓
处理时间线
  ↓
待补材料
  ↓
人工协助入口
```

### 12.3 时间线节点

- 已报案；
- 材料准备；
- 已提交；
- 审核中；
- 结果通知。

当前节点使用深靛蓝或蓝紫高亮，完成节点使用绿色，待处理节点使用橙色。

### 12.4 异常和协助

如果 Mock 状态为“待补材料”，展示：

- 缺少材料名称；
- 缺少原因；
- 补充材料按钮。

人工协助只展示客服入口和电话入口，不接入真实客服系统。

### 12.5 进度页验收

- [ ] 当前状态清晰突出；
- [ ] 时间线节点顺序正确；
- [ ] 待补材料可以回到闪赔页面；
- [ ] 客服入口有明确反馈；
- [ ] 页面不承诺固定结案时效。

## 13. 产品对比页详细设计

### 13.1 页面目标

### 13.2 对比维度

- 免赔额；

## 14. 健康行动页详细设计

### 14.1 页面目标

通过低门槛健康任务展示“保险 + 健康陪伴”的长期价值。

### 14.2 页面结构

```text
健康总览
  ↓
今日目标
  ↓
连续打卡
  ↓
任务列表
  ↓
积分和权益说明
```

### 14.3 任务类型

- 今日步行；
- 饮水记录；
- 规律作息；
- 健康知识答题；
- 家庭成员共同打卡。

第一版只重点实现“今日步行”任务，其余任务作为静态展示。

### 14.4 完成反馈

### 14.5 健康页验收

- [ ] 连续打卡有视觉反馈；
- [ ] 任务说明清晰；
- [ ] 不把健康积分直接表述为保险定价结果。
