# 保险类产品亮点功能调研

## 1. 调研目的

本文档整理《太平通2.0-设计调研报告.html》中提到的竞品能力和差异化设想，并结合公开产品资料进行二次筛选，形成适合太平通 2.0 微信小程序原型的功能参考。

目标不是复制竞品，而是回答三个问题：

1. 市场上的保险产品正在把用户体验做到哪一步；
2. 哪些能力适合进入太平通 2.0 原型；
3. 哪些能力需要降低承诺、延后验证或暂不纳入。

## 2. 核心判断

保险产品的竞争重点正在从“在线购买保险”转向：

> **保单资产管理 + AI 理解 + 理赔协助 + 医疗服务 + 家庭保障 + 健康陪伴**

太平通 2.0 最适合形成的产品组合是：

> **吉象 AI 顾问 + 家庭保障总览 + 保单随存随懂 + 闪赔协助 + 健康行动**

这五项能力可以形成从发现风险、理解保单、处理事故到持续健康管理的闭环。

## 3. 市场产品亮点

### 3.1 平安金管家：从保单管理到综合服务管家

公开资料显示，平安金管家覆盖保单、财富、健康、生活和客户服务，并强调保单查询、续费提醒、保单变更、保障额度与保障缺口展示，以及医疗、养老、健康等服务整合。

可借鉴：

- 保险资金区：把保额、待缴、可领取、可借等信息集中呈现；
- 保障缺口：从展示保单转向解释用户还缺什么；
- 按生命周期组织服务：投保、缴费、保全、理赔、续期分别提供下一步动作；
- 将健康和养老服务与保单关联，而不是单独做资讯频道；
- 精简底部导航，首页优先展示用户当前最需要处理的事项。

不直接照搬：会员等级、积分商城和大型俱乐部生态属于运营体系，不是本次原型的核心功能。

参考：[平安金管家官网](https://gj.pingan.com/)、[平安金管家 App Store 说明](https://apps.apple.com/cn/app/%E5%B9%B3%E5%AE%89%E9%87%91%E7%AE%A1%E5%AE%B6-%E5%80%BC%E5%BE%97%E4%BF%A1%E8%B5%96%E7%9A%84%E8%B4%A2%E5%AF%8C%E7%94%9F%E6%B4%BB%E7%AE%A1%E5%AE%B6/id549421060)

### 3.2 蚂蚁保：产品决策和理赔信任

现有调研报告将蚂蚁保作为首要对标，重点关注 AI 顾问、智能理赔、产品页理赔案例、同品类产品对比和普惠产品矩阵。

可借鉴：

- 产品详情页直接展示保障责任、适合人群和理赔案例；
- 同类产品使用统一维度进行对比；
- 用大白话回答“保什么、不保什么、谁适合”；
- 把电子保单、查询和理赔入口放在购买后继续使用的服务链路中；
- 通过客观解释降低用户对复杂条款和理赔结果的理解成本。

需要谨慎：报告中的具体用户量、凭证数量、准确率和调解比例应视为调研材料中的待核实信息，不在原型中作为产品承诺。

参考：[支付宝平台保险服务](https://zhifubaobaoxian.alipay.com/)

### 3.3 水滴保：家庭风险和保险服务闭环

水滴保公开介绍了家庭风险测评、产品对比、智能核保、家庭保单共享、缴费提醒、保全和代理赔等能力。

可借鉴：

- 以家庭为单位组织保险，而不是只显示当前登录人的保单；
- 用年龄、职业、收入结构、健康情况和家庭责任生成风险画像；
- 保单共享、保存、管理和追溯形成家庭资产视图；
- 在续费、退保、受益人变更等低频服务上提供明确的办理入口；
- 产品推荐前先做需求和风险分析，避免“商品货架式”推荐。

参考：[水滴保保险服务](https://www.sdbao.com/service)

### 3.4 众安保险：数字化保单和高频互动

众安公开产品说明中包含保单查询、保单下载、电子发票、快速理赔、家庭保障计划、理赔进度通知、保单智能解读和健康答题积分等能力。

可借鉴：

- “保单随存随懂”：电子保单保存后自动提取重点；
- 理赔记录和进度通知：让用户知道当前卡在哪一步；
- 家庭保单一键管理；
- 用健康答题、积分和兑换权益提高低频保险产品的使用频率；
- 围绕宠物、旅行、骑行、少儿等具体风险场景设计产品入口。

参考：[众安保险客户服务](https://www.zhongan.com/service)、[众安保险 App Store 说明](https://apps.apple.com/cn/app/%E4%BC%97%E5%AE%89%E4%BF%9D%E9%99%A9-%E6%99%BA%E8%83%BD%E4%BF%9D%E9%99%A9%E5%8A%A9%E7%90%86/id1019481423)

### 3.5 中国人寿寿险：语音和材料智能化

中国人寿寿险 App 的公开说明包含语音理赔、OCR 辅助填写、电子回单、按出险原因提示材料、保单和财富资产集中展示等能力。

可借鉴：

- 通过语音降低复杂服务的输入门槛；
- 通过 OCR 识别身份证、票据和诊断材料，减少重复填写；
- 根据事故类型动态提示材料清单；
- 生成电子回单，让用户拥有明确的申请凭证；
- 将“可领取、待缴、待还”等状态直接放进资产总览。

参考：[中国人寿寿险 App Store 说明](https://apps.apple.com/cn/app/%E4%B8%AD%E5%9B%BD%E4%BA%BA%E5%AF%BF%E9%99%A9/id765577833)、[中国人寿寿险理赔流程](https://www.chinalife.com.cn/chinalife/personal-service/life-insurance/claim-settlement-service/)

### 3.6 平安健康：保险与医疗服务融合

平安健康公开介绍了在线投保、智能核保、线上理赔、健康管理、在线问诊、医院预约和运动奖励等能力。

可借鉴：

- 保险购买、理赔和医疗服务放在同一服务链路中；
- 就医前提供咨询、预约和分诊；
- 就医中提供直接结算或费用协助；
- 就医后提供康复和健康管理；
- 运动行为与积分或服务权益关联。

不直接承诺：商保直付网络、医院数量、理赔时效和健康数据定价都需要真实业务和合规能力支撑，原型只展示流程概念。

参考：[平安健康保险 App](https://m.health.pingan.com/app/download/download_pc.html?from=m_h5)

### 3.7 中国人保：关怀版和基础服务完整性

中国人保公开服务入口覆盖在线理赔、理赔查询、保单查询下载、发票下载、批改和退保服务，并提供关怀版入口。

可借鉴：

- 关怀版不是单纯放大字体，还要减少层级和操作步骤；
- 保单、发票、单证和理赔记录集中管理；
- 高频服务在首页或服务大厅直接可达；
- 语音辅助、人工客服和家人协助作为复杂业务的兜底路径。

参考：[中国人保服务大厅](https://e-cdn.piccgroup.cn/)、[中国人保关怀版](https://e.picc.com.cn/caringVersion/)

## 4. 从现有设计报告筛选出的功能矩阵

### 4.1 P0：适合当前微信小程序原型

| 功能 | 优化后的定义 | 原型表现 |
| --- | --- | --- |
| 吉象 AI 顾问 | 基于预设场景回答保单和保障问题 | 推荐问题、对话回复、结果卡片 |
| 家庭保障中心 | 以家庭成员为单位查看保单和风险 | 家庭成员卡片、保障总览、缺口提示 |
| 保单随存随懂 | 将保单内容提炼为摘要和重点提示 | 保障责任、除外责任、下一步动作 |
| 保单健诊 | 对全家保障做可视化检查 | 保障雷达、重复保障、保障缺口 |
| 闪赔协助 | 用流程引导用户准备理赔材料 | 事故类型、材料清单、提交成功 |
| 理赔进度 | 把处理节点和待补材料透明呈现 | 时间线、当前状态、人工协助 |
| 产品对比 | 用统一维度比较同类产品 | 保额、保费、范围、免赔额对比 |
| 理赔案例 | 在产品页展示典型理赔场景 | 案例摘要、赔付结果、流程说明 |
| 银发模式 | 大字、高对比、少层级和家人协助 | 一键切换主题和字号 |

### 4.2 P1：适合后续原型或正式产品规划

| 功能 | 价值 | 前置条件 |
| --- | --- | --- |
| 家庭风险测评 | 帮助用户发现保障缺口 | 家庭信息模型和测评规则 |
| 语音理赔 | 降低输入门槛 | 语音识别、业务字段映射 |
| OCR 材料识别 | 减少手工填写 | 影像识别、材料审核规则 |
| 医疗服务联动 | 将保险与就医服务打通 | 医疗服务供应链和权益规则 |
| 健康任务与积分 | 提升使用频率 | 任务体系、积分和权益系统 |
| 续费和保全提醒 | 降低漏缴和错过服务的风险 | 真实保单状态和消息触达 |
| 保险知识学习 | 降低用户理解门槛 | 内容体系和权益设计 |

### 4.3 P2：长期探索，不纳入当前核心方案

| 功能 | 暂缓原因 |
| --- | --- |
| AI 闪应用生成 | 技术展示性强，但与保险核心服务距离较远 |
| 3D、视频等复杂 AI 输出 | 增加实现成本，不能直接提升当前汇报主流程 |
| 健康数据直接参与保险定价 | 涉及精算、隐私和产品条款，不能仅凭原型承诺 |
| 商保直赔码 | 需要医院、药店、医保及结算系统协同 |
| 自动调解和固定结案时效 | 处理结果和时效不能由前端单方面保证 |
| 大型健康 IP 活动 | 属于运营和市场增长项目，不是基础产品功能 |
| 一分钱送设备、跨界联动 | 需要预算、供应链和活动运营支撑 |

## 5. 太平通 2.0 推荐设计

### 5.1 首页主线

首页不再以功能宫格为主，而采用“状态 + 建议 + 行动”的结构：

```text
用户当前保障状态
  ↓
今天最值得处理的事项
  ↓
吉象 AI 给出解释
  ↓
用户进入保单、理赔、家庭或健康服务
```

建议首页模块：

1. 用户问候和保障状态；
2. 吉象 AI 顾问卡片；
3. 待办事项，如续费、补材料和保障缺口；
4. 家庭保障摘要；
5. 快捷服务；
6. 健康行动。

### 5.2 五项核心亮点

#### 吉象 AI 顾问

定位为“保险解释和服务导航”，而不是直接替代人工或做医疗诊断。

推荐问题：

- 我有哪些医疗保障？
- 家里谁的保障比较薄弱？
- 这张保单什么时候续费？
- 这次住院可能需要准备什么材料？

#### 家庭保障总览

以“我的家”为入口，展示父母、配偶、子女的保障卡片，并以颜色或标签区分已覆盖、待关注和存在缺口。

#### 保单随存随懂

将复杂条款转成四个区块：

- 保什么；
- 不保什么；
- 什么时候可以用；
- 下一步怎么办。

#### 闪赔协助

当前原型只模拟“拍照上传”和“材料识别后的清单确认”，不宣称真实审核结果、固定处理时长或自动理赔。

#### 健康行动

使用健康目标、打卡、积分和权益兑换构成轻量闭环。当前原型建议用步行任务和积分反馈，不直接绑定保费或免赔额。

### 5.3 视觉设计语言

本项目参考 `/Users/shen/Studio/Work/太平通2.0/2.0原型UI/UI风格参考` 下的 AI 问答、健康、我的和数据页面，确定采用：

> **浅薰衣草 + 玻璃感白卡 + 深靛蓝 + 蓝紫渐变 + 吉象 IP**

设计要点：

- 页面使用浅薰衣草或低饱和蓝紫背景，减少纯白背景带来的生硬感；
- 内容使用大圆角白卡承载，结合轻微透明、柔和阴影和细边框；
- 深靛蓝作为标题、核心数据和选中状态颜色；
- 蓝紫渐变用于吉象 AI、主按钮和关键引导；
- 健康反馈使用翡翠绿，待处理和风险提醒使用柔和橙色；
- 功能入口采用两列圆角卡片，减少密集宫格；
- 数据使用圆环进度、数字指标、趋势标签和时间轴表达；
- 底部导航采用悬浮胶囊样式，选中项使用深靛蓝高亮；
- AI 助手使用太平通自有“吉象” IP，不直接复用参考图中的角色、名称或文案；
- 吉象定位为解释、提醒、引导和陪伴型助手，不表现为医疗诊断者或理赔决策者。

这套视觉语言服务于“让复杂保障更容易理解”的产品目标：用柔和的背景和卡片降低信息压力，用清晰的数据和下一步动作提高决策效率。

## 6. 设计和合规边界

- AI 输出必须标注为信息辅助，不替代理赔、核保或医疗结论；
- 产品推荐应先展示依据和适用范围，不使用“最优”“保证获赔”等绝对表述；
- 理赔页面展示“预计处理节点”时，应避免承诺固定结案时间；
- 真实理赔案例需要脱敏、授权和可追溯来源；
- 健康数据采集必须说明用途、范围、保存方式和授权关系；
- 银发版的家人代办需要在正式产品中设计授权、身份验证和操作留痕；
- 当前原型所有数据均使用 Mock，不展示真实个人、保单和医疗信息。

## 7. 原型汇报建议

推荐在汇报中只演示三条主线：

### 主线一：AI 查询保单

首页 → 吉象 AI → 推荐问题 → 保单摘要 → 查看保障详情。

### 主线二：家庭保障诊断

首页 → 我的家 → 选择家庭成员 → 查看缺口 → 获取建议。

### 主线三：闪赔协助

首页 → 我要理赔 → 选择事故类型 → 材料清单 → 提交成功 → 进度时间线。

健康行动和银发模式作为补充亮点展示，不抢占主流程。

## 8. 结论

市场调研支持太平通 2.0 从“保险功能入口集合”转向“家庭风险管理服务”。当前版本应聚焦理解、管理和协助三件事：

1. 帮用户看懂自己的保障；
2. 帮用户管理全家的保单；
3. 在理赔和健康场景中给出下一步行动。

大型营销活动、真实 AI、直赔网络和健康定价可以作为长期方向保留，但不应在本次原型中作为已具备能力展示。
