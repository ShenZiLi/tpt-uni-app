# 技术设计

## 总体架构

采用单包 uni-app 工程：页面负责组合业务区块，组件负责视觉和交互复用，`src/mock` 提供演示数据和模拟异步行为，`src/styles` 维护全局设计令牌。

```text
pages
  ↓
components + composables
  ↓
mock data / mock async actions
  ↓
uni-app runtime → 微信小程序
```

## 目录边界

- `src/pages/**`：路由页面和页面级状态。
- `src/components/**`：跨页面复用的卡片、按钮、吉象头像、TabBar 等。
- `src/mock/**`：只读演示数据和模拟异步方法，不依赖网络。
- `src/styles/**`：颜色、圆角、阴影、间距、文字层级和公共页面样式。
- `src/types/**`：页面领域类型和通用状态类型。
- `pages.json`：Tab 与非 Tab 路由配置。

## 数据与状态

使用本地模块状态和页面 `ref`/`computed`，不引入 Pinia，避免原型阶段增加状态管理成本。跨页面交互通过 URL 参数和 Mock 数据完成；提交类操作只更新当前页面的演示状态。统一状态类型为 `idle | loading | success | empty | error`。

## 视觉实现

- 页面底色使用浅薰衣草渐变。
- 内容容器使用半透明白卡、背景模糊和大圆角。
- 主操作使用深靛蓝或蓝紫渐变，状态色采用翡翠绿/柔和橙。
- 采用大留白、卡片分组、圆形指标和悬浮胶囊导航。
- 吉象使用本地 CSS/emoji 占位表现，保留后续替换正式 IP 素材的边界。

## 兼容与取舍

原型优先保证微信开发者工具可运行和汇报流程可重复；不依赖真实接口、不实现复杂权限和文件能力。uni-ui 作为依赖保留，用于基础反馈/表单能力；核心视觉组件使用项目自定义组件，避免被默认主题限制。

## 风险与回滚

若微信端构建对某个 CSS 能力支持不一致，回退为纯色背景和普通白卡；若 uni-ui 安装或构建异常，保留自定义组件完成演示，不阻塞页面交付。每个阶段独立提交，便于按 commit 回滚。
