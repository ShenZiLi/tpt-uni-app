# 太平通 2.0 · 微信小程序原型

> 从「功能堆叠型保险服务台」升级为「AI 风险管理伙伴」的保险服务小程序高保真原型。
> 基于 uni-app + Vue 3 + TypeScript，全量本地 Mock 数据，不依赖任何后端即可完整演示。

## 项目简介

| 维度 | 说明 |
| --- | --- |
| 产品定位 | 以「吉象 AI 顾问」串联保险、家庭与健康场景的风险管理伙伴 |
| 原型形态 | 可在微信开发者工具中启动、可逐页点击操作的高保真原型 |
| 数据来源 | 纯本地 Mock（`src/mock`），不发起任何网络请求 |
| 核心场景 | AI 问保障、保单随存随懂、闪赔协助、家庭保障、保单健诊、健康陪伴 |
| 工程目标 | 3～5 分钟内完成至少两条完整演示链路，无需登录、无需等待接口 |

## 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | uni-app | Vue 单文件组件开发，除微信小程序外可扩展 H5 等端 |
| 视图 | Vue 3 | 组合式 API + `<script setup>` |
| 语言 | TypeScript | 为 Mock 数据与页面状态预留类型约束 |
| 构建 | Vite | uni-app Vue3 版默认构建方案 |
| 组件库 | uni-ui | 仅用于基础控件，品牌视觉与核心卡片全部自定义 |
| 状态 | 页面内 `ref` + `uni.setStorageSync` | 原型阶段不引入 Pinia，状态复杂度不足以支撑全局管理 |

## 快速开始

环境要求：Node.js 18+、微信开发者工具（仅微信端预览需要）。

```bash
# 安装依赖
npm install

# 微信小程序：编译到 dist/dev/mp-weixin，再用微信开发者工具「导入项目」指向该目录
npm run dev:mp-weixin

# H5 预览
npm run dev:h5

# 生产构建 / 类型检查
npm run build:mp-weixin
npm run type-check
```

说明：

- `src/manifest.json` 中 `appid` 为空，导入微信开发者工具时选择自己的 AppID 或使用测试号即可。
- H5 端仅作快速预览，原型的设计与验收目标是微信小程序端。

## 页面清单

底部导航为悬浮胶囊式，共 4 项：**首页** / **AI 顾问** / **保单** / **我的**。其余页面从首页卡片或服务入口进入。

| 页面 | 路径 | 说明 | 归属 |
| --- | --- | --- | --- |
| 首页 | `pages/index/index` | 问候与保障状态、吉象 AI 入口、待办事项、家庭保障完整度、快捷服务 | TabBar |
| AI 顾问 | `pages/ai/index` | 推荐问题、可控演示对话、思考态与业务结果卡片 | TabBar |
| 我的保单 | `pages/policy/index` | 保单摘要列表与分类筛选 | TabBar |
| 我的 | `pages/mine/index` | 个人信息、家庭成员、收藏记录、体验设置入口 | TabBar |
| 保单详情 | `pages/policy/detail` | 保障责任、缴费信息、服务入口 | 二级页 |
| 家庭保障 | `pages/family/index` | 家庭成员与保障完整度 | 二级页 |
| 保单健诊 | `pages/family/diagnosis` | 保障缺口清单与 AI 分析建议 | 二级页 |
| 闪赔协助 | `pages/service/claim` | 事故类型选择、材料清单、发起申请 | 二级页 |
| 理赔进度 | `pages/service/claim-progress` | 提交结果与进度时间线 | 二级页 |
| 产品对比 | `pages/service/compare` | 保障范围、保额、保费、免赔额横向对比 | 二级页 |
| 健康行动 | `pages/service/health` | 健康任务、完成反馈与积分变化 | 二级页 |
| 主题设置 | `pages/mine/theme` | 三套主题预览与保存 | 二级页 |

> 页面分两类：首页、AI 顾问、保单、我的、主题设置为逐页定制实现；保单详情、家庭保障、保单健诊、闪赔、理赔进度、产品对比、健康行动复用通用内容页组件 `FeaturePage` 承载演示内容，重点在于把流程演示闭环，而非逐页精雕。

## 演示链路

**A · AI 查保障**：首页 → 问问吉象 → 选择推荐问题 → 思考态 → 回复 + 保障摘要卡片 → 查看保障详情 → 保单详情

**B · 闪赔服务**：首页 → 闪赔协助 → 选择事故类型 → 材料清单 → 开始申请 → 提交成功 + 进度时间线

**C · 家庭保障**：首页 → 家庭保障 → 选择成员 → 保障缺口 → 让 AI 帮我分析 → 建议结果

**D · 健康行动**：首页 → 健康行动 → 任务列表 → 完成今日步行 → 任务完成反馈 + 积分更新

## 视觉规范

设计关键词：**浅薰衣草背景、半透明白卡、深靛蓝文字、蓝紫渐变、高留白、圆角胶囊、轻量拟人化 AI**。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `$ink` | `#20255f` | 主文字、核心数据、主要操作 |
| `$ink-soft` | `#686d96` | 辅助文字、说明信息 |
| `$lavender` | `#f1efff` | 次级按钮底色、浅色容器 |
| `$purple` | `#6b5cf5` | 主强调色，AI 与选中态 |
| `$green` | `#31a982` | 健康、完成、正向趋势 |
| `$orange` | `#f29a62` | 待处理、风险提醒 |
| 页面背景 | `linear-gradient(155deg, #f6f4ff, #ebeaff 52%, #f5f8ff)` | 页面底色 |
| 玻璃卡 | `rgba(255,255,255,.82)` + `blur(18px)` + 圆角 `36rpx` | 内容容器 |

交互原则：一个页面只突出一个主操作；所有演示按钮都必须能完成闭环；不展示「暂无功能」的死入口；动效只用淡入、滑入、加载态等轻量形式。

吉象 IP 规则：吉象是太平通自有的服务伙伴，承担解释、提醒、引导和陪伴角色，不表现为医疗诊断者或理赔决策者；对话采用短句与大白话，明确下一步动作。

## 原型边界声明

本仓库是**演示原型**，不是可上线产品。原型阶段明确不做，且代码中不存在对应能力：

- 真实登录、实名认证与手机号授权；
- 真实保单查询、核保、投保与支付；
- 真实理赔材料上传与审核；
- 真实大模型调用与敏感数据处理；
- 运营后台、埋点系统与权限体系；
- 正式多端发布适配。

所有 AI 回复、理赔状态和健康数据均为 Mock，仅用于展示交互与产品理念，**不代表任何真实的核保、理赔、医疗或保险推荐结论**。
